# 03. 改善を 1 つ実装する

## いつ・誰が
- docs/backlog.md の候補を 1 件ずつ（2 人とも、午前も午後も）
- 1 セッション = 1 候補。終わったら `/clear`
- Claude はデプロイの前で止まる。人の OK のあと、デプロイ → ベンチ（ブラウザ）→ 結果投稿まで Claude が進める

## 貼るプロンプト
````text
docs/backlog.md の候補 <<ID>> を実装して、ベンチで確かめてほしい。担当: <<sue か yochi>>。補足: <<あれば>>

1. 準備: CLAUDE.md と候補の元の docs/review/ を読む。backlog の状態を「着手中」にする。直近のスコアを docs/bench-log.md から拾う
2. ブランチ: main を pull してから `<担当>/<短い内容>` を切る
3. 一考: CLAUDE.md「守ること」の 5 点を 1 行ずつ答えて私に見せる。怪しければ止まる
4. 実装: CLAUDE.md「スコア 0 にしない」に従う。差分は最小
5. ビルド: CLAUDE.md のビルドコマンドと `go vet ./...`。2 回続けて失敗したら止まる
6. PR: commit は 1〜2 個。draft PR を作る。本文はテンプレートに沿い、先頭に候補 ID、末尾に一考 5 行と戻し方
7. デプロイ（止まる）: 「<ブランチ> をデプロイしてよいか」と聞いて待つ。OK 後に SKILL bench の deploy.sh。動作確認を 1 つ（初期化が 200 を返す等）
8. ベンチ: SKILL bench の流れ（bench-start.sh → ポータルで実行 → bench-end.sh → bench-report.sh）
9. 判定: SKILL newrelic-nrql で狙った数値が変わったか見る。PASS かつスコア上昇 → 採用。横ばいなら狙った数値の改善で判断。下がった・FAIL → 不採用。迷ったらもう 1 回ベンチ
10. 後始末: 採用なら PR を ready にしてマージ（私の OK 後）→ main をデプロイし直す。不採用なら main をデプロイし直し（OK 後）、PR に理由を書いて close。docs/bench-log.md に 1 行（時刻 / 担当 / コミット / 変更内容 / スコア / PASS・FAIL / 前回比 / メモ）、backlog の状態と PR URL を更新。新しく見つけたボトルネックは backlog に追記

最後の報告: 採用 / 不採用とスコアの前後、変わった計測値 2〜3 個、次に効きそうな候補 1〜2 件
````

## 補足
- 午後の大物は、02-C の分割案の 1 つ目だけを候補 ID に指定する
- 2 人が同時に実装してよい。デプロイとベンチだけは 1 本ずつ順番に回す
