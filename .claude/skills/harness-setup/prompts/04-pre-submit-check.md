# 04. 再起動試験と提出前の掃除

## いつ・誰が
- A. 再起動試験: 終了 90 分前（すー）。よちは作業を止めて待機
- B. 掃除と最終ベンチ: 終了 50 分前（すー）。よちは最終確認リストを目で確認
- 終了 15 分前以降は変更しない。最後のベンチが PASS したらその状態で終える
- 再起動・停止は Claude がコマンドを用意し、人の OK 後に実行する

## A. 再起動試験
````text
ISUCON の再起動試験をやる。目的は追試（主催者の再起動 → ベンチ → データ確認）で失格しないことの確認。
終了時刻: <<HH:MM>>
1. CLAUDE.md「再起動で壊さない」と docs/restart-test.md を読む。2 人に作業停止を頼む Discord の文面を 1 行用意する
2. 確認（読み取りのみ、表にする）: デプロイ済みコミット = main HEAD、サーバー上の手作業差分、必要なサービスが enabled、不要なサービスが停止、主催者のサービスが元のまま、df -h。問題があれば直すコマンドを提示して OK を待つ
3. 直近のベンチで書かれたデータを 3 件控える（主要テーブルの最新行と取得 API）。docs/restart-test.md の末尾に追記する
4. 再起動（止まる）: 全サーバーを再起動するコマンドを提示して OK を待つ。起動後に ssh が通ることを確認する
5. 再起動後: 全サービス active、控えたデータが API と DB で取れる、トップページが 200、SKILL bench でベンチ
6. PASS かつスコアが直前から大きく落ちていなければ合格。docs/bench-log.md に「再起動試験」で 1 行。NG なら原因と対処案（03 の流れで小さく直す）
報告: 合否、直したこと、残るリスク
````

## B. 掃除と最終ベンチ
````text
最終提出に向けて計測用の設定を外し、最終ベンチを通したい。ベンチ PASS が最優先。
終了時刻: <<HH:MM>>
1. ブランチ `<担当>/final-cleanup` で 1 PR: nginx の access_log off、MySQL の slow_query_log / general_log OFF、pprof・デバッグ用エンドポイント・余計なログ出力を外す。各項目がベンチの挙動を変えないことを 1 行で確認する。ビルドを通す
2. サーバー側（コマンド提示 → OK 後）: NewRelic を全台で止める（`.claude/skills/newrelic-setup/toggle.sh off`）、計測用の常駐ツールを止める、不要なサービスを disable --now、大きなログを空にする、df -h
3. デプロイ（止まる）: OK 後に掃除ブランチをデプロイ。初期化が 200 を返すことを確認。SKILL bench でベンチ。PASS ならマージ（OK 後）。FAIL なら掃除前の main に戻してもう一度ベンチ
4. 最後の確認リスト（表で返す）: 最後のベンチが PASS、全サーバー起動、必要なサービス enabled、主催者のサービスが元のまま、ポータルのサーバー一覧が 1 スタック（人が目で確認）、デプロイ済みコミット = main HEAD、bench-log に記録、以後触らない
````

## 終了後
- 主催者のアナウンスまでサーバーに接続しない。競技内容を外に出さない
